## Confirmed, partial and unknown enums

Confirmed card enums:

- rarity `0..5` → N/R/SR/SSR/UR/LR;
- element ones digit `0..4` → AGL/TEQ/INT/STR/PHY;
- element band `0x` → unawakened, `1x` → Super, `2x` → Extreme;
- attack style strings `Normal`, `Hyper`, `Condition`, `Extra` → Super, Ultra, Unit, EX.

Confirmed passive efficacy types currently implemented: `1, 2, 3, 4, 5, 9, 13, 16, 18, 20, 24, 28, 48, 51, 59, 60, 61, 67, 68, 76, 78, 81, 90, 91, 96, 98, 101`, plus scoped efficacy-`110` removal, efficacy-`111` attack-break and efficacy-`120` counter behavior. Type 24 proves a defender-side boolean presence marker that suppresses the normal element-affinity guard result unless the independent efficacy-78 override is present. Its handler and guard consumer do not apply `eff_value1..3` or the DB31 operation to this decision; target is supported, 33/34 timings are bounded to player-attack setup, and the damage bucket/final formula/recurrence remain partial. Type 28 proves that `eff_value1` is narrowed to float32 percentage points, aggregated by deck index and raw skill category in float32 record order, and applied to the signed player-attack damage value that is also displayed and mission-counted. The truncated result reaches a raw type-2 HP factor. Its handler and consumer do not apply DB31 `calc_option`; final HP capping/application, probability ordering, reset/expiry and interaction with other factor types remain unknown. Types 59/60 prove single-stat ATK/DEF selection while both read `eff_value1`, narrow it to float32 and set the proportional flag; type 61 proves paired ATK/DEF modifiers from `eff_value1/2`. All three families scale through the signed int32 value at obtained-ball map key raw `11` before the DB31 operation; the raw BallType-11 semantic name, count population/reset window and recurrence remain partial. Type 98 proves `eff_value1` as a signed int32 increment after truncation toward zero, `eff_value2` as the signed cap and `eff_value3 = 0..5` as attack modifier, defense modifier, critical probability, dodge probability, resist-damage rate and battle-gauge modifier output selectors. Its aggregate starts at zero and traverses stored 40-byte entries from vector begin to end; every signed 32-bit add wraps modulo `2^32` before the sign-directed cap. The current increment is appended before the fold when a local gate returns bit 0 clear. The structural append branch, history fold and replacement operation are supported, while the gate's event semantics, reset/expiry and cross-status scope remain partial. Type 110 proves the exact four-field removal selector and status mutations, while SkillType/category names and scheduling remain unknown. Type 111 proves a parameterless per-enemy marker and first-N eligible current-action selection; its structured target enum, activation and lifecycle remain unknown. Type 120 proves `eff_value1 → resistDamageRate`, `eff_value2 → increaseDamagePercent`, and `eff_value3 → battleScriptNo`; it does not yet prove activation or damage-calculation behavior. Some numeric types have both mapped and unknown rows because their parameters or subfamilies are not universally proved.

Confirmed `SkillCalcOption` values are `0 → lhs + rhs`, `1 → max(lhs - rhs, 0)`, `2 → lhs + lhs × rhs / 100`, `3 → max(lhs - lhs × rhs / 100, 0)` and `4 → rhs` with `lhs` ignored. Native single-precision rounding is preserved at each arithmetic step. The enum proof is limited to operation: it does not imply unit, target, execution timing, calculation bucket, duration, recurrence or stacking. Values outside `0..4` remain unknown even though positive out-of-range native dispatch currently falls back to addition, because negative values index before the table and neither behavior defines an enum member.

Confirmed passive execution timing: `exec_timing_type = 1` selects the native turn-start execution event. Values `4` and `5` select bounded player-attack setup and post-damage setup events. Values `6` and `7` are bounded inside `EnemyAttackDamageAndActionBank::setup`: 6 precedes counter-finish, disable-attack, absorb, dodge and intermediate damage calculation; 7 follows that calculation plus received-attack and dodge/guard mission bookkeeping, before attacking-condition assembly. None of these setup labels asserts hit, HP application, animation execution or Super Attack identity. Observed values `3, 9, 11, 12, 14, 15` remain unknown. No supported timing automatically implies a calculation bucket or settles `turn`, `is_once`, duration, recurrence or stacking.

Confirmed basic-stat buckets: efficacy `1` reads `eff_value1` into ATK, efficacy `2` reads `eff_value1` into DEF, and efficacy `3` reads `eff_value1` into ATK plus `eff_value2` into DEF. The native former-passive-stat consumer selects timings `1, 3, 11, 15, 18`; the latter-passive-stat consumer selects `4, 5, 6, 7, 9, 14`. These bucket identities do not promote unknown execution-event labels. For this consumer, calc options `0/1/4` use stat-point operands and `2/3` use percentage points of the current stat. Modifiers materialize through `float32`, accumulation is in `double`, flat changes truncate toward zero, negative percentage multipliers floor at zero, and the last assignment in efficacy-list order wins. Cross-bucket ordering, target selection and lifecycle dimensions remain unknown; timing `12` is not assigned to either bucket and future rows outside the proved groups remain lossless with bucket `unknown`.

Confirmed passive target candidate scopes: `target_type` values `1/2/3/4` select the ability owner, player-party deck indices `0..6`, the stored runtime enemy target with ability-owner fallback, and the current enemy vector respectively. Values `12/13` filter player-party candidates with raw awakening-class predicates `{1,3}` / `{2,3}`; `14/15` apply those predicates to enemy candidates; `16` structurally excludes the ability owner from the player party under the independently proved category-0 passive precondition. These are candidate sets before the native sub-target predicate. Slot `6` is null, slots `0,5,7..11` are absent from projected passive rules and out-of-range values remain unknown. Target selection does not imply timing, operation, unit, calculation bucket, duration, recurrence, expiry or reset.

Confirmed passive sub-target semantics: `passive_skills.sub_target_type_set_id` reaches the runtime set getter and the `AbilityStatusEfficacy` membership predicate. Filters are applied sequentially to the prior result, proving AND/intersection composition; an empty set returns the original candidate vector and duplicate filters are reapplied. Value types `1/2` include/exclude a structured `card_categories.id`; values `4/5` include/exclude a `card_unique_info_set_id` whose members come from `card_unique_info_set_relations` and are compared with `Card::getCardUniqueInfoId`. Value `3` constructs the distinct metamorphic filter but remains partial and is absent from projected passive rules. Out-of-domain values remain unknown. Sub-target filtering does not imply target construction, timing, operation, unit, calculation bucket or lifecycle.

Confirmed passive lifecycle field mechanics: the row constructor stores `turn` separately and normalizes `is_once` by a native zero/nonzero test. The latter gates viability as `is_once == 0 || exec_count < 1`; successful execution reloads current turn from the maximum, sets executed-this-turn and increments exec count. On an eligible end-turn update, after independent status, availability and internal-turn gates, nonnegative current turn decrements by one and a nonpositive result clamps to zero and deactivates the status. Raw `-1` bypasses the decrement, while the separate `isEndTurn` predicate still tests `current < 1`; it is therefore a partial sentinel, not a proved `forever` enum. End turn clears executed-this-turn independently. `clearExecCount` is proved to zero every status counter, but its trigger/epoch is unknown, so no once-per-turn/battle/appearance label is promoted. All current projected `turn` values are positive. Lifecycle does not imply condition, target, timing, operation, unit, bucket or stacking.

Confirmed condition families include the earlier SQLite projections for causality types `1, 2, 5, 15, 16, 19, 24, 25, 30, 38, 42`, selector masks from type `46`, and native-backed runtime types `3, 4, 34, 43, 51, 55, 67`. Types `3/4` compare a truncated float32 battle-gauge/cap100 percentage with `cau_val1` using `>=` / strict `<`; their raw status-category gate and current-character deck-index selection are explicit, while gauge reset/evaluation timing remains partial. Type `67` reads `cau_val1` as a handler submode, `cau_val2` as its selector and ignores `cau_val3`: current submode 0 requires exact structured category membership and submode 2 requires native class masks `32 → {1,3}` / Super or `64 → {2,3}` / Extreme for all seven resolved party slots. Its dispatched submode 1, other element masks and scheduling remain unknown. Type `49` has a supported Super Attack category selector backed by `special_categories.raw_attribute` and the native bitmask consumer. Types `17/18/33` have supported target-HP metrics, parameters and inclusive comparators, with runtime scope/gates kept explicit. Types `47/54` have supported revival-activation counter predicates: ability-owner pure-current record for 47, and deck indices 0–6 across pure/back current records for 54, whose `cau_val1` zero/nonzero value selects any/none. These families remain partial at activation/history level. Types `40` and `56` have partial native predicates over `AdditionalParam` byte 1, but their attack kind, direction and scope are unknown. Type `41` preserves 602 name tokens but lacks a first-party dictionary. Remaining numeric causalities stay raw/unknown even when the native dispatch slot has been identified.

No enum is promoted solely from a symbol name, localized description, parser parity, or statistical correlation.
