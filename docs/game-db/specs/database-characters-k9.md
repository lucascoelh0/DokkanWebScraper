## Field authority frontier

K0/K1 identity and state graph, K2 taxonomy, K3 supported mechanics and K4 raw
base-card stats/caps are shadow candidates. They remain subordinate to the
current production/FYI/DokkanInfo consumers until a field-scoped shadow run and
migration contract pass. K3 raw skill/presentation content and K6 asset
references are audit-only. K5 dynamic acquisition/availability remains
server-owned; K4 EZA/SEZA stat overrides and all combat results remain
unsupported.

Server dependencies are schedules/availability, banners/summons, dynamic
acquisition/rewards, asset manifest/CDN/delivery, authentication and server-only
roots. FYI still supplies current localized presentation, latest-state
conditions/rendering, production Team Analysis inputs and unsupported-mechanic
fallback. DokkanInfo still supplies the legacy production catalog shape,
portrait/card-art URL conventions and fallback outside the FYI subset.

## Update strategy

A new app/DB requires new read-only decrypted inputs and a new explicit
profile. Changed SQLite, ELF or semantic evidence must undergo the relevant
bounded revalidation before reuse; the refresh path never silently replays or
inherits DB0–DB50. Generate DB1 and K0–K7 sequentially, retain per-gate
determinism and the 1 GiB memory gate, then run K8 compatibility finalization
and K7 shadow parity before proposing any field-authority change. Commit,
optional publication and production/Android activation remain separate
authorized actions.
