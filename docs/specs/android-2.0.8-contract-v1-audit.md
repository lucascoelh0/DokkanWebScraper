# Android 2.0.8 consumer-contract audit

**Date:** 2026-08-23  
**Status:** static audit, typed v1 projection, frozen full-corpus decoder and R8 manager/cache smoke complete; publisher routing pending

## Scope

This audit compares the public production pair consumed by Android 2.0.8 at
commit `6ac55fe` with the public staging candidate generated by parser `1.9.14`.

| Dataset | Production | Staging candidate |
|---|---|---|
| Characters | `2026-08-22T21:14:10.019Z`, SHA `34b2ce3918d0497b458f106f4e00b50cb039f0a280ef6bfe45c0ca76ee1a84bd` | `2026-08-23T20:26:24.615Z`, SHA `578fe9ca44dafb9037ce35e3b88a57f12d315fd5ab39ba91837023f39eca6d53` |
| Team Analysis | parser `1.9.0`, SHA `d7a8461c41484b0e25f61131476006b18eadad71c6bac265e7f0e289e7a96237` | parser `1.9.14`, SHA `0f9e3c74e96119d43388852fa3d5d0b48b53b3e5bd5c251b60c941c848a805b7` |

The comparison traversed every JSON path and runtime JSON type in 1,436
Characters and 2,288 Team Analysis states. It also compared staging wire
discriminators with the frozen Android 2.0.8 enums and conversion fallbacks.

## Manifest and runtime bounds

- Both Team Analysis releases declare `schemaVersion = 1` and
  `rulesVersion = 1`. Android 2.0.8 requires those exact values but accepts any
  nonblank `parserVersion` whose payload matches the manifest.
- Staging Team Analysis is 3,077,757 compressed and 55,433,108 uncompressed
  bytes, below the old 10,000,000 and 64,000,000 byte limits. Its 2,288 states
  are below the old 10,000-state limit.
- The minified 2.0.8 rules preserve `TeamAnalysis*Wire`, Character seed, Super
  Attack and the release dataset wire models involved here.

## Structural findings

### Characters

- No existing JSON path changed runtime type and no production path was
  removed.
- All 44 new paths are descendants of the optional
  `activeSkillDetails[].activationCondition` field.
- Only Ultimate Gohan `1025561` and Gohan (Beast) `1034341` carry that new
  Character-side block in this candidate.
- The 2.0.8 Gson target does not declare the field and therefore ignores it.
  Existing fields retain their production shapes.

**Static classification:** wire-compatible and expected to load. The typed
Active Skill activation condition is unavailable to the old client.

### Team Analysis

- No common JSON path changed runtime type.
- The candidate adds 199 optional paths, primarily state-level Active Skill
  activation conditions, typed predicate evidence, combat-event provenance and
  effect-scaling detail.
- Four production-only paths disappear: optional condition `sourceText` at
  three AST depths and four occurrences of an optional deep predicate `value`.
  Recognized condition operators do not require those fields.
- Android 2.0.8 wire discriminators are nullable strings converted through
  explicit fallbacks. Unknown enum strings become `UNKNOWN`; unknown scaling
  kinds become `TeamAnalysisEffectScaling.Unknown`; unknown Gson fields are
  ignored.

**Static classification:** no identified deserialization, manifest, size,
state-count or R8 hard failure. This is not semantic compatibility.

## Semantic degradation in Android 2.0.8

- Parser `1.9.14` emits typed Active Skill activation conditions for 343
  states. Android 2.0.8 ignores that entire field.
- Against production parser `1.9.0`, the old mapper encounters 1,247 rules in
  519 states whose condition operator is already `unknown`.
- Against staging parser `1.9.14`, 751 rules in 466 states contain at least one
  discriminator or scaling construct outside the old domain model. Comparing
  stable rule IDs, 810 previously affected rules become understood, 437 remain
  affected and 314 newly use a construct outside the old model.
- Of those newly affected rules, 88 condition rules across 66 states contain a
  predicate kind absent from Android 2.0.8:

| New predicate kind | Rules |
|---|---:|
| `guard_activated` | 30 |
| `ki_sphere_collection_order` | 14 |
| `next_attacking_turn` | 10 |
| `finish_effect_activated` | 8 |
| `ally_category_name_present` | 7 |
| `character_ko` | 7 |
| `character_category` | 6 |
| `incoming_attack_from_enemy_hit_by_self_super_attack` | 3 |
| `all_rotation_allies_obtained_ki_sphere` | 2 |
| `giant_form_ended` | 1 |

- The remaining newly affected reasons overlap rules and concern effect or
  timing detail: 135 new scaling usages, 74 `per_turn` application triggers,
  35 repeated-threshold combat-event modes, 24 new evaluation moments, three
  `sweet_treat` Ki-sphere values and two new relative timings. These map to
  old `UNKNOWN` representations rather than throwing.

Examples include Super Janemba's Ki-sphere collection order, Hit's incoming
attack from an enemy hit by his Super Attack, Syn Shenron's per-category ally
scaling and Buu (Kid)'s repeated attack thresholds.

## Decision

Do not promote the unprojected staging pair to the root v1 manifests. The
evidence predicts graceful structural loading, not a startup crash, but the old
client would silently lose new Active Skill conditions and degrade newly typed
passive rules. Keeping `schemaVersion = 1` and `rulesVersion = 1` is insufficient
evidence of consumer compatibility.

Treat the current staging bytes as a v2 candidate. A v1 projector should:

1. omit Character and Team Analysis Active Skill activation-condition fields;
2. replace unsupported predicate kinds or enum values with the explicit v1
   partial/unknown representation while retaining explanatory source text;
3. omit or downgrade unsupported scaling and application-trigger detail rather
   than emitting v2-only discriminators;
4. preserve all v1-required state, passive, effect and Super Attack shapes;
5. validate the projected pair through a frozen 2.0.8 decoder over the complete
   corpus, then through a minified staging build before promotion.

The projector is a compatibility serializer over the canonical official-DB
model, not a second parser.

## Executed frozen v1 consumer

The Android repository now contains an executable corpus harness at
`scripts/compat/android-v1-6ac55fe/`. It does not compile the current decoder.
The runner verifies and archives the exact full commit
`6ac55fe20872d8c3ee1678d4e34fc010243ebb51` into an ignored temporary workspace,
injects one test into that snapshot, and runs only its `domain` consumer.

The Character half calls the frozen `RoomCharacterDatabaseGateway.openPayload`
path over the entire decompressed payload. That includes the 2.0.8 Gson seed
contract, character-count and unique-ID validation, Character/Transformation
materialization, release skill normalization, and derived leader-boost work.
The Team Analysis half runs the frozen `TeamAnalysisPayloadReader.validate`,
then reads and converts all state ordinals through the frozen wire-to-domain
mapper. The harness independently verifies manifest pairing, compressed size
and SHA-256, uncompressed size, and the 2.0.8 size/count limits before reporting
success.

Two complete public pairs were downloaded read-only and executed:

| Corpus | Result | Characters | Team states | Passive rules | Super Attacks |
|---|---|---:|---:|---:|---:|
| production `2026-08-22T21:14:10.019Z` / parser `1.9.0` | pass | 1,436 | 2,288 | 11,694 | 2,703 |
| staging `2026-08-23T20:26:24.615Z` / parser `1.9.14` | pass | 1,436 | 2,288 | 11,691 | 2,703 |

The staging execution used Characters SHA
`578fe9ca44dafb9037ce35e3b88a57f12d315fd5ab39ba91837023f39eca6d53`
and Team Analysis SHA
`0f9e3c74e96119d43388852fa3d5d0b48b53b3e5bd5c251b60c941c848a805b7`.
The production execution used the hashes recorded in the scope table above.

This proves complete non-minified structural decoding and materialization by
the exact v1 code. It does not make the unprojected staging semantics v1-safe.
It also intentionally decouples local corpus decoding from the staging object-
key prefix: Android 2.0.8's production transport reads the root manifest and
its private URL validator does not accept staging-prefixed keys. The eventual
projected root-v1 manifest still needs its exact manager/cache path plus a
minified APK smoke.

## Executed typed v1 projection

The local-only `android-v1-contract-projector` now implements the compatibility
serialization defined above. It has no network or publisher dependency and
requires four explicit canonical input files plus a fresh output directory.
It validates compressed and uncompressed sizes, hashes, counts, Character/Team
pairing and payload/manifest metadata before projecting either dataset.

The staging `1.9.14` corpus produced this local v1 pair:

| Dataset | Compressed bytes | Uncompressed bytes | SHA-256 |
|---|---:|---:|---|
| Characters | 2,342,681 | 28,935,308 | `039a87def97b0f0772301cb5ca8779370d3c9176a5b040aadd50a7844521ec25` |
| Team Analysis | 2,970,224 | 54,468,842 | `61b90af9f9a254f915844b185e43482c945f060fc2ff4cdc4377bc32b72c327e` |

The projector omitted two Character-side and 343 Team Analysis-side Active
Skill activation-condition blocks. It converted 214 unsupported condition
leaves or enum values to the explicit v1 `unknown` condition with source text,
765 unsupported effect scalings to v1 unknown scaling and 210 `per_turn`
application triggers to v1 unknown triggers. Composite condition structure and
supported siblings remain intact. It then recalculated the corpus as 9,365
supported, 2,295 partial and 31 unknown passive rules. The projected Team
manifest references the projected Character SHA exactly.

Four focused tests cover all Active Skill nesting positions, canonical-input
immutability, selective preservation of supported v1 nodes, explicit downgrade
of v2-only condition/scaling/trigger discriminators and fail-closed rejection
of unprojected values. The exact frozen `6ac55fe` consumer accepted and fully
materialized the projected pair: 1,436 Characters, 2,288 states, 11,691 passive
rules and 2,703 Super Attacks.

No publisher, object key, R2 object or production manifest changed. These
artifacts remain ignored local evidence rather than a release candidate.

## Executed R8 manager/cache smoke

The Android repository now also owns
`scripts/compat/android-v1-6ac55fe-minified/`. Its runner archives the same
exact `6ac55fe20872d8c3ee1678d4e34fc010243ebb51` source and creates an isolated
`compatV1` app variant that inherits release shrinking and optimization. A
non-empty R8 `mapping.txt` is mandatory before installation.

The generated main-APK Activity, itself processed by R8, seeds the supplied
bytes into the real Character and Team Analysis cache directories with the
network base URL forced blank. It then runs `DatabaseBootstrapper`, queries the
materialized Room Character repository, refreshes `TeamAnalysisRepository` and
loads every projected state key through the minified wire-to-domain mapper.
The test application ID is separate from production and is removed on success.

Projector output intentionally retains publisher-neutral local filenames. For
this transport gate the runner changes only each copied manifest's `fileName`
to the root-v1 content-addressed key shape required by Android 2.0.8. Payload
bytes, hashes, versions, sizes, counts and Character/Team binding remain exact.
Compressed payloads use neutral names only while embedded as test assets so
AAPT cannot strip their `.gz` suffix; the seeded cache files retain the real
legacy names.

The final emulator execution passed after `minifyCompatV1WithR8`:

- 1,436 Room Characters, Character SHA
  `039a87def97b0f0772301cb5ca8779370d3c9176a5b040aadd50a7844521ec25`;
- 2,288 Team Analysis states, 11,691 passive rules and 2,703 Super Attacks,
  Team SHA
  `61b90af9f9a254f915844b185e43482c945f060fc2ff4cdc4377bc32b72c327e`.

The two setup failures preceding the pass were harness-only and fail-closed:
AAPT's special handling of `.gz` test assets, then the frozen manager's strict
legacy Team Analysis object-key requirement. Neither failure reached a decoder
with different payload bytes or changed a public object.

## Executed typed publisher routing dry-run

Characters and Team Analysis publishers now require an explicit
`--contract-lane v1|v2`. Production v1 retains the legacy root keys, while the
other routes are isolated under `v2/`, `staging/v1/` and `staging/v2/`.
Publisher state records the lane and uses a lane-scoped default path, preserving
the existing root-v1 state path for backward-compatible production history.

The v1 route additionally requires the exact projector report. Both publishers
verify its projector version, frozen consumer commit, paired output manifests
and Character/Team SHA binding before planning delivery. The v1 semantic gate
accepts only shapes supported by the frozen contract; the canonical v2 gate
continues to use the current strict Team Analysis validator.

Read-only remote dry-runs against the absent `staging/v1` manifests produced:

| Dataset | Planned new bytes | Manifest key |
|---|---:|---|
| Characters | 2,343,137 | `staging/v1/characters-manifest.json` |
| Team Analysis | 2,970,938 | `staging/v1/team-analysis-manifest.json` |
| **Combined** | **5,314,075** | — |

Wrangler reported the bucket as `388 MB`. Applying the existing conservative
rounding and both planned additions gives a combined upper bound of
394,314,075 bytes against the 10,000,000,000-byte limit. No `put`, `delete`,
manifest write, state write or input-artifact mutation occurred.

## Residual boundary

The projected pair is now published under the isolated `staging/v1` lane.
Public HTTP verification proved `no-store` manifests, immutable payload cache
headers, exact compressed sizes and SHA-256 values, and exact Character/Team
binding. A post-publication dry-run reported both payloads and manifests
aligned with no planned writes.

The R8-minified frozen `6ac55fe` manager/cache harness also passed using the
same payload bytes downloaded back from R2: 1,436 Characters, 2,288 Team
Analysis states, 11,691 passive rules and 2,703 Super Attacks. Public HTTP later
returned byte-identical payload hashes.

Wrangler 4.118.0 twice reported a successful Team Analysis payload upload while
the object remained absent. The manifest correctly stayed unpublished because
post-upload verification failed. Repeating the exact immutable upload with
Wrangler 4.125.0 produced an immediately readable object with the expected
size and SHA, after which the publisher safely promoted and verified the
manifest. The repository now pins Wrangler `^4.125.0`.

Production root-v1, production v2 and the older unversioned staging lane were
not changed. Remaining boundaries are a separately authorized root-v1
promotion and Play-delivered signing; neither is authorized by this checkpoint.
